# ShaderPlayground — UI 전면 개편 디자인 요청서

> **대상**: 사내 디자이너
> **요청 성격**: 현재 UI를 폐기하고 처음부터 다시 만드는 **전면 리디자인**. 아래에 나오는 화면·기능은 "제품이 무엇을 하는가"를 설명하기 위한 것이지, 현재 화면 레이아웃을 재현하라는 뜻이 아니다. 레이아웃·비주얼은 백지에서 새로 제안해 달라.
> **요청 산출물**: 풀 디자인 시스템 + 전 화면 하이파이 시안 + 인터랙션 프로토타입 (→ §10)
> **문서 언어**: 한국어 / **제품 UI 라벨 언어**: 영어
> **버전**: v1 · 작성일 2026-07-12

## 0. 30초 요약 (먼저 읽어주세요)

**ShaderPlayground**는 브라우저에서 도는 **노드 기반 셰이더(그래픽 프로그램) 플레이그라운드**다. 사용자는 화면 위에서:

1. **노드 그래프**로 메시·이미지·셰이더 등을 블록처럼 연결하고,
2. 연결한 셰이더의 **GLSL 코드를 인라인 에디터에서 작성**하고,
3. 그 결과를 **3D 뷰포트에서 실시간으로** 본다.

즉 **① 노드 그래프 · ② 코드 에디터 · ③ 실시간 3D 뷰포트**가 한 화면에 공존하는 **전문가용 크리에이티브 개발 도구**다. 가장 가까운 친척은 아래와 같다:

- **Blender 셰이더 에디터** — 노드로 셰이더를 짜고 카드마다 미리보기 썸네일이 뜬다
- **TouchDesigner / Cables.gl** — 노드로 실시간 비주얼을 만든다
- **Shadertoy** — GLSL 프래그먼트 셰이더를 브라우저에서 실시간 미리보기
- **VSCode** — 코드 에디터의 편집 경험(자동완성·에러 표시·심볼 이동)

이 도구의 핵심 긴장은 **"입문자도 시작할 수 있을 만큼 친절하되, 전문가가 오래 써도 답답하지 않을 만큼 밀도 높은"** UI다. 이 균형이 이번 리디자인의 성패를 가른다.

> ⚠️ **디자이너에게**: 이 문서에는 uniform, FBO, 포트, 컴퓨트 노드 같은 그래픽스 용어가 나온다. **모두 몰라도 된다.** §14 용어집에 다 정리해 뒀고, 디자인상 알아야 할 건 "그게 화면에서 어떤 요소로 보이는가"뿐이다. 막히면 언제든 물어봐 달라.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 제품명 | **ShaderPlayground** (확정. 로고·워드마크는 이번에 신규 제작) |
| 플랫폼 | 웹 앱 (데스크톱 브라우저 전용, Chrome/Edge/Firefox/Safari) |
| 기술 스택 | React 18 · WebGL2 · CodeMirror 6 (코드 에디터) · React Flow (노드 그래프) |
| 현재 상태 | 기능은 성숙(30+ 개발 페이즈 완료). **UI/비주얼만 미완성** — 그래서 이 요청 |
| 이번 범위 | 앱 내부 UI 전체 + 브랜드 비주얼 아이덴티티(로고·컬러·톤). 마케팅 사이트는 범위 밖(§11) |

**이번 리디자인을 하는 이유**: 기능은 계속 붙여왔지만 UI는 기능을 얹기 위한 임시 골격 수준이다. 밀도·일관성·시각적 완성도·브랜드감이 없다. 제품의 실제 역량에 걸맞은 "완성된 도구"의 얼굴을 갖추는 것이 목표다.

## 2. 디자인 목표 & 성공 기준

### 2.1 디자인 목표 (우선순위 순)

1. **캔버스 우선(canvas-first)** — 결과물(3D 뷰포트)과 노드 그래프가 주인공. UI 크롬(툴바·패널·버튼)은 작업을 감싸되 시선을 뺏지 않는다.
2. **밀도와 접근성의 균형** — 전문가가 원하는 정보 밀도를 유지하면서, 입문자가 첫 5분에 길을 잃지 않는 온보딩/기본값.
3. **일관된 시각 문법** — 노드 13종, 포트 6종, 상태(에러/선택/녹화)들이 **예측 가능한 색·형태 규칙**을 따른다. 한 번 배우면 어디서든 통한다.
4. **오래 봐도 편한 화면** — 장시간·저조도(작업실/야간) 세션 전제. **다크 테마가 기본**, 라이트는 옵션(§7.6).
5. **브랜드 아이덴티티 확립** — 이름만 있는 상태. 이 도구만의 성격(정밀함 + 창의성 + 약간의 실험적 무드)을 시각화.

### 2.2 성공 기준 (측정 가능하게)

- 신규 사용자가 **도움말 없이** 노드 3개(mesh → shader → output)를 연결해 화면에 무언가를 띄우기까지 성공.
- 노드 종류/포트 타입을 **색·아이콘만으로 구분** 가능(라벨을 읽지 않아도).
- 12+ 종 패널/모달/토스트가 **하나의 디자인 시스템**에서 파생되어 보인다(짜깁기 느낌 0).
- 다크/라이트 양쪽 모두 WCAG AA 대비 충족(§9).

### 2.3 Non-goals (이번에 하지 않는 것)

- 기능 추가·제거 제안(정보 구조 개선 제안은 환영, 신규 기능 설계는 별건).
- 모바일/태블릿 최적화(데스크톱 우선. 반응형은 창 크기 대응 수준 §9).
- 마케팅 랜딩페이지·문서 사이트.

## 3. 타깃 사용자 & 사용 맥락

### 3.1 페르소나

| 페르소나 | 설명 | 니즈 |
|---|---|---|
| **GLSL 입문자 / 학생** | 셰이더를 배우는 중. 코드보다 시각적 실험으로 감을 잡고 싶음 | 명확한 시작점, 프리셋/예제, 실시간 피드백, 친절한 에러 |
| **테크니컬 아티스트** | 셰이더를 실무에 쓰는 아티스트. 노드로 빠르게 프로토타이핑 | 밀도, 키보드 단축키, 다중 미리보기, 파라미터 즉시 조정 |
| **크리에이티브 코더 / VJ** | 제너러티브 비주얼·라이브 퍼포먼스 제작 | 실시간성, 녹화(GIF/WebM), 공유, 풀스크린 몰입 |

### 3.2 사용 환경

- **디바이스**: 데스크톱/노트북, 마우스+키보드. 큰 화면(≥1440px) 주력, 최소 1280px 대응.
- **환경**: 어두운 작업실·야간 작업 잦음 → 다크 우선.
- **세션**: 한 번 켜면 오래(30분~수시간). 눈의 피로·시각적 소음 최소화가 중요.
- **워크플로**: 마우스(노드 드래그·연결)와 키보드(코드 작성·단축키·커맨드 팔레트)를 오간다.

### 3.3 대표 사용자 여정 (디자인 시 이 흐름을 상상)

1. 앱을 연다 → 데모 그래프가 이미 돌고 있다(빈 화면 아님).
2. 노드를 추가(툴바 또는 Cmd+K 커맨드 팔레트)하고 포트를 드래그해 연결한다.
3. 셰이더 노드를 선택 → 하단 코드 에디터에 GLSL이 뜬다 → 코드를 고치면 1~2프레임 안에 뷰포트가 바뀐다.
4. 코드에 `uniform float u_intensity;`를 추가 → 오른쪽 인스펙터에 슬라이더가 자동 생성 → 드래그로 실시간 조정.
5. 마음에 들면 **녹화(GIF/WebM)** 하거나 **공유 URL** 복사, 또는 **HTML로 export**.

## 4. 제품 기능 범위 / 화면 인벤토리

디자인해야 할 "표면" 전체 목록이다. 상세 요구는 §5.

```
┌─────────────────────────────────────────────────────────────┐
│  Top: Toolbar (노드 팔레트 · 프리셋 · 녹화 · export · share)      │
├──────────────────────┬──────────────────────────────────────┤
│                      │                                       │
│   Node Editor        │        Viewport (3D 결과, 1~4분할)      │
│   (노드 그래프 캔버스)   │        + Viewport Controls · Time bar   │
│   - 노드 카드 13종      │                                       │
│   - 포트/엣지          ├──────────────────────────────────────┤
│   - 라이브 썸네일       │        Side Panel (탭 전환)             │
│   - 그룹/미니맵         │        Inspector / Assets / Problems    │
│                      │                                       │
├──────────────────────┴──────────────────────────────────────┤
│  Code Editor (선택 노드의 GLSL · vertex/fragment 탭 · 에러 표시)  │
├─────────────────────────────────────────────────────────────┤
│  Status Bar (fps · draw calls · GPU 시간 · 에러 수)             │
└─────────────────────────────────────────────────────────────┘
   Overlay: Command Palette (Cmd+K) · Modals · Toasts
```

> 위 배치는 **현재 구조를 참고용으로 보여줄 뿐**이다. 3-분할이든, 도킹 가능한 패널이든, 탭 기반이든 — **레이아웃 자체를 새로 제안해도 좋다.** 단, 세 주역(그래프·뷰포트·코드)이 동시에 또는 빠르게 오갈 수 있어야 한다는 제약만 지켜 달라.

**전체 화면/컴포넌트 인벤토리** (모두 시안 대상):

- **A. 메인 레이아웃 & 셸** — 앱 프레임, 패널 배치/리사이즈/도킹, 반응형 거동
- **B. 노드 에디터** — 캔버스, 노드 카드(13종), 포트(6종), 엣지, 미니맵, 줌/팬, 그룹, 다중 선택
- **C. 뷰포트** — 3D 렌더 영역, 1/2/3/4 분할, 카메라 컨트롤, 배경, 빈 상태(placeholder)
- **D. 뷰포트 컨트롤 & 타임바** — 재생/정지/스크럽/배속, 카메라 리셋/FOV, GPU 타이머 토글
- **E. 코드 에디터** — vertex/fragment 탭, 라인/에러 표시, 자동완성·hover 팝업, 다중 선택 배너
- **F. 사이드 패널** — Inspector / Assets / Problems 탭 + 노드별 인스펙터 8종
- **G. 툴바** — 노드 팔레트, 프리셋, 녹화(WebM/GIF), export, share, clear
- **H. 커맨드 팔레트** — Cmd+K 퍼지 검색 오버레이
- **I. 상태바** — 성능 지표 표시줄
- **J. 모달 & 다이얼로그** — Help, 세션 복구, 확인/알림
- **K. 토스트** — 비침습 알림(성공/경고/에러/정보)
- **L. 빈/로딩/에러 상태** — 각 영역의 상태 디자인 (§8)
- **M. 브랜드** — 로고/워드마크, 앱 아이콘/파비콘, 스플래시 또는 첫인상

## 5. 영역별 요구사항 (핵심)

### 5.A 메인 레이아웃 & 셸

- 세 주역(노드 에디터·뷰포트·코드 에디터)이 한 화면에 공존. **각 영역 리사이즈 가능** 여부, 접기/펼치기, 도킹 방식 등은 제안 환영.
- 크롬(툴바·상태바·패널 헤더)은 얇고 조용하게. 콘텐츠 영역을 최대화.
- 사용자가 "지금 어디에 집중해야 하는지"가 명확해야(포커스 상태).

### 5.B 노드 에디터 & 노드 카드 ★가장 중요

이 도구의 시각적 정체성의 절반이 여기서 결정된다.

**노드 종류 13종** — 각각의 시각적 정체성(카테고리 색/아이콘)을 설계:

| 카테고리 | 노드 | 성격 |
|---|---|---|
| 소스(입력) | `Mesh` `Image` `Webcam` `Video` `Audio` | 그래프에 데이터를 공급. 출력 포트만 있음 |
| 처리 | `Shader` `Compute` | GLSL 코드를 실행. 입력·출력 모두 있음. **셰이더가 주역** |
| 출력 | `Output` | 화면에 그려질 최종 지점 (그래프당 1~4개) |
| 값/유틸 | `Param`(Float/Vec3/Color/Time) `Math` `Swizzle` `Combine` | 숫자·색·값을 만들고 가공. 작은 노드 |
| 컨테이너 | `Group` | 노드들을 시각적으로 묶는 배경 프레임. 접기/펼치기 가능 |

**노드 카드에 들어가는 요소** (셰이더 카드 기준, 밀도 높음):

- 타이틀(노드 이름) + 종류 아이콘
- **라이브 썸네일** — 셰이더/이미지 노드 카드 안에 **96×96 실시간 미리보기**가 계속 갱신됨 (Blender 스타일). 카드의 핵심 시각 요소.
- **입력 포트(왼쪽) / 출력 포트(오른쪽)** — 포트마다 라벨 + 타입별 색 동그라미
- 우상단 메타 칩: `0.42ms`(GPU 시간), 에러 뱃지(빨간 점/카운트)
- 선택 상태, 다중 선택 상태, 에러 상태, 컴퓨트 노드(썸네일 대신 vertex 수/primitive 메타)

**포트 타입 6종** — 각각 고유색(연결 가능 여부를 색으로 직관화):
`mesh` · `texture` · `float` · `vec2` · `vec3` · `vec4`
→ **엣지(연결선)도 포트 색을 따른다.** 타입이 안 맞으면 연결 불가 — 이 피드백의 시각 언어 필요(드래그 중 유효/무효 표시).

**엣지/연결 인터랙션**: 드래그로 연결, 유효/무효 하이라이트, 1:N 분기 허용, 삭제. 곡선/직각 등 엣지 스타일 제안.

**기타**: 미니맵, 줌/팬 컨트롤, 그룹 프레임(라벨·색·접힘 헤더), 다중 선택(박스 셀렉트).

> **제약**: 노드 그래프는 **React Flow(@xyflow/react)** 위에 구현된다. 커스텀 노드/엣지/핸들 스타일은 자유롭지만, 라이브러리의 기본 인터랙션(줌/팬/연결 핸들 히트영역)은 존중하는 편이 구현 비용상 유리하다. 과감한 재해석을 원하면 미리 상의.

### 5.C 뷰포트 (3D 결과)

- WebGL 캔버스가 실시간 렌더. **1/2/3/4 분할 레이아웃** (Output 노드 개수에 따라):
  - 1 = 전체 / 2 = 좌우 / 3 = 상단 2 + 하단 1 / 4 = 2×2
- **빈 상태(placeholder)** — Output이 없을 때의 화면(배경색 + 안내). "뭘 해야 하는지" 힌트를 주는 온보딩 기회.
- 카메라: 마우스로 궤도 회전(좌드래그)/이동(우드래그)/줌(휠). 배경색 커스텀.
- **몰입/풀스크린 모드** 고려(VJ·발표용) — 제안 환영.

### 5.D 뷰포트 컨트롤 & 타임바

- **타임 컨트롤**: 재생/정지(Space), 스크럽 슬라이더, 0~4× 배속. 셰이더의 시간(`u_time`)을 제어.
- **카메라 컨트롤**: Reset 버튼, FOV 슬라이더(10°~120°).
- **GPU 타이머 토글**: 켜면 노드별 렌더 시간(ms) 표시.
- 이들을 뷰포트 위 오버레이 바로 둘지, 별도 영역에 둘지 제안.

### 5.E 코드 에디터 (GLSL)

VSCode 수준의 편집 경험을 목표로 한다.

- **vertex / fragment 탭** — 선택한 셰이더 노드의 두 코드 스테이지를 탭 전환. **탭 헤더에 에러 표시(빨간 점)**.
- **인라인 에러** — 컴파일 에러가 나는 라인에 빨간 밑줄 + 마우스오버 메시지.
- **LSP 기능** — 자동완성 팝업, 심볼 hover 툴팁, 정의로 이동, 참조 하이라이트, 이름 변경, 시맨틱 하이라이팅(변수/함수/타입 색 구분).
- **다중 선택 배너** — 노드를 2개 이상 선택하면 "여러 개 선택됨" 상태 표시.
- 코드 폰트(monospace) 선정 필요(§7.4).

> **제약**: 코드 에디터는 **CodeMirror 6** 기반. 신택스 하이라이팅 테마·거터·툴팁 스타일은 커스터마이즈 가능. 완전한 에디터 UI 재발명은 비용이 크니 "테마+주변 크롬" 중심으로.

### 5.F 사이드 패널 (Inspector / Assets / Problems)

탭으로 전환되는 우측 패널. **선택한 노드에 따라 인스펙터 내용이 완전히 바뀐다.**

- **Inspector** — 선택 노드의 속성 편집. 노드 종류별 8종의 인스펙터:
  - **Uniform 컨트롤** ★ — 셰이더의 uniform이 자동으로 컨트롤이 됨: `float`→슬라이더, `vec2/3/4`→다축 슬라이더, 색→**컬러 피커**, `bool`→토글. GLSL 주석으로 범위/라벨/컨트롤 종류를 오버라이드하는 GUI 에디터도 있음.
  - Param / Utility(Math·Swizzle·Combine) / Webcam / Video / Audio / Group 인스펙터 — 각각 고유 컨트롤(디바이스 선택, 재생 컨트롤, FFT 설정, 그룹 라벨/색 등).
- **Assets** — 임포트한 메시/이미지 카탈로그(썸네일 그리드), 드래그&드롭 임포트, "노드로 추가" 버튼.
- **Problems** — 모든 노드의 컴파일 에러/런타임 에러를 한곳에. 클릭하면 해당 노드 선택 + 코드의 그 라인으로 점프. **탭 헤더에 에러 카운트 뱃지**.

→ 슬라이더·다축 슬라이더·컬러 피커·토글·셀렉트·숫자 입력 등 **폼 컨트롤 라이브러리**가 여기서 대량으로 필요하다(§7.5).

### 5.G 툴바

- **노드 팔레트** — 노드 추가(13종). 카테고리 그룹핑.
- **프리셋** — 예제 그래프 로드.
- **녹화** — WebM 녹화(●Record/■Stop, 녹화 중 빨간 강조), GIF 녹화(진행률 표시).
- **Export** — 단일 HTML 파일로 내보내기.
- **Share** — 현재 작업을 URL로 인코딩해 공유.
- **Clear / Undo / Redo**.

### 5.H 커맨드 팔레트 (Cmd+K)

- 퍼지 검색 오버레이. 노드 추가·프리셋 로드·명령 실행을 키보드만으로. (VSCode/Raycast/Linear 스타일)

### 5.I 상태바

- fps · 프레임 수 · draw calls · 총 GPU 시간(ms) · 에러 수. 얇고 조용한 하단 바.

### 5.J 모달 & 다이얼로그

- **Help** — 단축키/도움말.
- **세션 복구** — 재접속 시 "이전 작업을 복구할까요?"(백업 시각·노드 수 표시, 복구/새로 시작 2버튼).
- 확인/알림 다이얼로그 일반형.

### 5.K 토스트

- 비침습 알림. 4종: **정보 / 성공 / 경고 / 에러**. 자동 소멸 + 수동 닫기.

## 6. 디자인 방향 / 톤 & 무드

### 6.1 무드 키워드 (출발점, 확정 아님)

**정밀한(precise) · 실험적인(experimental) · 몰입감 있는(immersive) · 프로페셔널 · 약간의 네온/발광감**

셰이더/그래픽스 도구 특유의 "빛을 다루는" 느낌 — 어두운 배경 위에 발광하는 요소, 정밀한 그리드, 색으로 말하는 데이터. 단, **화려함이 목적이 아니라 기능을 돋보이게 하는 수단**.

### 6.2 레퍼런스 (참고 — 베끼지 말고 해석)

| 레퍼런스 | 배울 점 |
|---|---|
| **Blender 셰이더 에디터** | 노드 카드 + 카드 내 미리보기, 밀도, 다크 |
| **TouchDesigner / Cables.gl** | 노드 그래프의 시각 문법, 실시간 비주얼 도구의 무드 |
| **VSCode (다크)** | 코드 에디터, 정보 밀도와 가독성의 균형 |
| **Figma / Linear** | 패널·툴바·커맨드 팔레트의 현대적 크롬, 컴포넌트 완성도 |
| **Shadertoy** | 셰이더 커뮤니티의 친숙한 관례(iMouse 등) |

> **피하고 싶은 것**: 장난감 같은 과한 라운드/그림자, 저대비 회색 위 회색, 아이콘 없이 텍스트만 빽빽한 밀도, 라이트 테마를 기본으로 한 눈부신 화면.

### 6.3 브랜드 (이름만 있음 → 신규 제작)

- **로고/워드마크** — "ShaderPlayground". 앱 아이콘/파비콘 포함.
- **브랜드 컬러** — UI 디자인 시스템과 연결. 셰이더/빛의 성격을 담되 UI에서 과하지 않게.
- 톤: 진지한 도구지만 "playground"라는 이름의 놀이/실험 정서를 한 스푼.

## 7. 디자인 시스템 요구사항

풀 디자인 시스템을 요청하므로, 아래를 **토큰화된 시스템**으로 산출해 달라.

### 7.1 컬러 토큰

- **표면(surface) 계층** — 배경/패널/카드/입력 등 다크 테마의 여러 레이어(elevation).
- **텍스트 계층** — primary/secondary/muted/disabled.
- **강조(accent)/브랜드 컬러** + 인터랙션 상태(hover/active/focus).
- **시맨틱** — success/warning/error/info (토스트·에러·상태바 공용).

### 7.2 노드 카테고리 색 (도메인 특화)

노드 5개 카테고리(소스/처리/출력/값·유틸/컨테이너)를 구분하는 **색 체계**. 노드 카드 헤더·아이콘 배경에 적용. 서로 충분히 구분되되 한 팔레트로 조화.

### 7.3 포트 타입 색 (도메인 특화) ★

**6종 포트 타입 각각의 고유색**: `mesh` · `texture` · `float` · `vec2` · `vec3` · `vec4`.
- 포트 동그라미 + 연결 엣지에 동일 적용.
- 색맹 고려(색만으로 구분하지 않도록 형태/라벨 병행 제안 환영).
- 이 6색은 이 도구에서 **가장 자주 반복되는 색 신호**다. 신중히.

### 7.4 타이포그래피

- **UI 폰트** — 라틴 기반(제품 UI가 영어). 밀도 높은 도구에 맞는 가독성 좋은 산세리프.
- **코드 폰트(monospace)** — GLSL 편집용. 리거처·가독성·라인 구분.
- 타입 스케일(캡션~헤딩), 라벨/뱃지/칩용 소형 사이즈 포함.

### 7.5 컴포넌트 라이브러리

최소 다음을 포함(상태 variant 포함 — default/hover/active/focus/disabled):

- 버튼(primary/secondary/ghost/icon/toggle), 아이콘 버튼
- **슬라이더 / 다축(2~4) 슬라이더 / 컬러 피커 / 토글 / 셀렉트 / 숫자·텍스트 입력** (인스펙터에서 대량 사용)
- 탭, 뱃지/칩(에러 카운트·GPU ms), 툴팁, 팝오버
- 패널 헤더, 리스트/트리 아이템, 카드
- 모달/다이얼로그, 토스트, 커맨드 팔레트 아이템
- 미니맵, 줌 컨트롤

### 7.6 테마

- **다크 = 기본.** 라이트 = 옵션(뷰어 토글). 두 테마 모두 토큰으로 파생.
- 코드 에디터 신택스 테마도 다크/라이트 양쪽.

### 7.7 아이콘 시스템

- 노드 13종 + 액션(재생/정지/녹화/export/share/undo 등) 다수. **일관된 그리드/스트로크의 커스텀 또는 선정된 아이콘 세트**. 셰이더/그래픽 성격에 맞게.

### 7.8 모션 / 인터랙션 원칙

- 실시간 도구라 UI 모션은 **빠르고 절제**되게(작업 방해 금지). 노드 연결·패널 전환·토스트 등장·녹화 상태 등 핵심 마이크로 인터랙션 정의.

## 8. 상태 & 엣지 케이스 (완성도의 핵심)

각 영역의 아래 상태를 반드시 디자인:

- **빈 상태** — 빈 그래프 첫 진입(온보딩 힌트), Output 없는 뷰포트(placeholder), 빈 Assets, Problems 0건.
- **로딩** — 에셋 임포트/디코드 중, 셰이더 컴파일 중.
- **에러** — 컴파일 에러(노드 뱃지 + 코드 밑줄 + Problems 목록), 런타임 에러, 카메라/마이크 권한 거부.
- **선택** — 단일 선택, **다중 선택**(노드·코드·인스펙터 각각의 표현).
- **진행 중** — **녹화 중**(빨간 강조·타이머), GIF 인코딩 진행률, 자동저장 표시.
- **오프라인/복구** — 세션 복구 다이얼로그.

## 9. 기술적 제약 & 고려사항

- **웹 앱 / React 18** — 컴포넌트 기반. 상태 많은 실시간 UI.
- **WebGL 캔버스 영역** — 뷰포트는 GL이 직접 그리는 캔버스. 그 위 오버레이 UI(컨트롤·분할 경계)만 디자인 대상.
- **React Flow(노드) / CodeMirror(코드)** — 위 §5.B·§5.E의 커스터마이즈 한계 참고. 과감한 재해석은 사전 상의.
- **성능** — 노드 카드마다 라이브 썸네일이 갱신되고 뷰포트가 실시간이라, UI는 **가벼워야** 한다. 무거운 블러/그림자/애니메이션 남용 지양.
- **반응형** — 모바일은 범위 밖. 단 **창 크기 변화(1280 ~ 초대형)에 레이아웃이 깨지지 않아야** 함. 패널 최소 폭·접힘 거동 정의.
- **접근성** — 다크/라이트 모두 **WCAG AA 대비**. 포커스 링. 색만으로 정보 전달 금지(특히 포트 6색·상태색).
- **국제화** — 지금은 영어 UI만. 단 라벨 길이 변화에 견디는 레이아웃(고정폭 남발 금지).

## 10. 산출물 & 형식

**요청 수준: 풀 디자인 시스템 + 전 화면 하이파이 시안 + 프로토타입.**

1. **디자인 시스템 파일** — 컬러/타이포/스페이싱/컴포넌트 토큰, 다크·라이트, 노드·포트 색 체계, 아이콘 세트.
2. **컴포넌트 라이브러리** — §7.5 전 컴포넌트를 상태 variant + 오토레이아웃으로. 개발이 그대로 매핑할 수 있게.
3. **전 화면 하이파이 시안** — §4 인벤토리 A~M 전부. 핵심 상태(§8) 포함.
4. **인터랙션 프로토타입** — 핵심 여정(§3.3): 노드 추가→연결→코드 편집→uniform 슬라이더→녹화/공유. 주요 마이크로 인터랙션.
5. **브랜드** — 로고/워드마크/앱 아이콘/파비콘 + 사용 규칙.
6. **개발 핸드오프** — 스펙/레드라인/토큰 export(가능하면 코드 토큰과 매핑 제안). 폰트·에셋 라이선스 명시.

- **도구**: Figma 권장(핸드오프·토큰·프로토타입 일원화). 다른 제안 가능.
- **파일 구조**: 페이지 단위로 정리(Foundations / Components / Screens / Prototype / Brand).

## 14. 부록 — 용어집 (디자이너용)

| 용어 | 쉬운 설명 | 화면에서는 |
|---|---|---|
| **셰이더 / GLSL** | 픽셀 색을 계산하는 작은 프로그램. GLSL은 그 언어 | 코드 에디터에 뜨는 코드 |
| **노드** | 기능 블록 하나(메시·이미지·셰이더·출력 등) | 그래프의 카드 |
| **포트** | 노드의 입력/출력 연결점 | 카드 좌우의 색 동그라미 |
| **엣지** | 포트끼리의 연결선 | 노드 사이 선 |
| **uniform** | 셰이더에 밖에서 넣는 값(숫자·색 등). 슬라이더로 조절 | 인스펙터의 슬라이더/컬러 피커 |
| **텍스처** | 셰이더가 읽는 이미지 데이터 | `texture` 포트, 이미지 노드 |
| **메시** | 3D 형상(구·큐브 등) | `mesh` 포트, Mesh 노드 |
| **FBO / 패스** | 셰이더가 그린 중간 결과(다음 셰이더의 입력) | 셰이더 체이닝, 카드 썸네일 |
| **컴퓨트 노드** | GPU로 파티클/시뮬레이션 계산 | Compute 노드(썸네일 없이 메타 표시) |
| **vertex / fragment** | 셰이더의 두 단계(형태 / 색) | 코드 에디터의 두 탭 |
| **썸네일** | 각 노드가 만든 결과의 실시간 미리보기(96×96) | 노드 카드 안 작은 화면 |
| **Output 노드** | 최종적으로 화면에 그려질 지점(1~4개) | 뷰포트 분할 수를 결정 |
| **Param/Math/Swizzle/Combine** | 값을 만들고 가공하는 작은 유틸 노드 | 작은 노드들 |
| **`u_time` / 타임 컨트롤** | 셰이더에 흐르는 시간(애니메이션의 원천) | 재생/정지/스크럽 바 |
