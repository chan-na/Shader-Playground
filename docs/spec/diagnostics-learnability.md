### Phase 15 — GPU Timer Overlay (완료)
- **`EXT_disjoint_timer_query_webgl2` 통합**: `core/gl/gpuTimer.ts` 의 `GpuTimerPool` 이 `TIME_ELAPSED_EXT` 쿼리로 각 ShaderPass / ComputePass 의 GPU 시간을 비동기로 측정. extension 미노출 환경(Safari 등)에서는 `create()` 가 null → 모든 begin/end 가 옵셔널 체이닝으로 no-op.
- **lifecycle**: thumbnail PBO 풀과 동형 — `begin/end/poll/release/dispose`. nested begin 은 무시(첫 활성 쿼리 유지). `GPU_DISJOINT_EXT` 발화 시 in-flight 쿼리 전부 폐기 후 다음 프레임 재시작.
- **`gpuTimerStore` (Zustand)**: 결과는 EMA(α=0.2) 로 평활해 `byNode[id]` 에 저장, `totalMs` 는 매 sample 시 합계 재계산. `supported`/`enabled` 두 flag — 둘 다 true 일 때만 `executePlan` 이 timer 인스턴스를 받음.
- **UI**: ShaderNodeView / ComputeNodeView 카드 우상단 `0.42ms` 칩(`node-card__gpu-ms`), StatusBar 우측에 합계 `12.3ms GPU`, ViewportControls 에 enable 체크박스 (지원 안 됨이면 `unavailable` 라벨). 칩은 `<0.01ms` 미만일 때 `<0.01ms` 표시.
- **lifecycle hooks**: Viewport recompile 시 사라진 노드 ID 에 대해 `pool.release` + `store.removeNode`. context lost → restored 경로에서 pool 을 재생성하고 supported flag 를 다시 반영.
- **검증**: Vitest 단위 18 건 (`gpuTimer.test.ts` 11 — extension probe / nest 방지 / 쿼리 재활용 / disjoint / release / dispose, `gpuTimerStore.test.ts` 7 — EMA / total / removeNode / supported·enabled 전이). Playwright E2E `phase-15-gpu-timer.spec.ts` 5 건 — (a) 스토어 shape 노출, (b) 칩 렌더 + ms 텍스트, (c) StatusBar GPU 컬럼 표시, (d) disable 토글이 UI 양쪽 다 숨김, (e) 노드 제거 시 `byNode` 에서 항목 정리.

### Phase 16 — 디버깅 · 진단 인프라 (완료)
개발자용 런타임 추적 인프라. 사용자 알림(`toastStore`)·GLSL 진단(`diagnosticsStore`)과 역할이 분리된, 평소 비가시 / 필요 시 열람하는 개발자 채널.
- **중앙 로거 `src/utils/log.ts`**: 레벨(`debug`/`info`/`warn`/`error`)·카테고리(`gl`/`render`/`graph`/`assets`/`external`/`autosave`/`app`)별 로깅 + 500개 인메모리 링버퍼(초과 시 오래된 것 evict) + 구독/내보내기 API(`subscribeLog`/`exportLogText`/`clearLogBuffer`). 콘솔 미러링은 DEV 한정 + `minLevel` 게이트, 버퍼는 레벨과 무관하게 항상 기록. 어떤 store 도 import 하지 않는 leaf util (단방향).
- **전역 안전망**: `main.tsx` 의 `window.onerror`/`unhandledrejection` 핸들러 → `log.error("app", …)`. `ErrorBoundary`(메인 작업 영역만 감쌈)가 렌더 중 uncaught 를 잡아 폴백 UI(새로고침 / 진단 복사) 제공.
- **침묵 catch 추적화**: registry/audio·videoLoader/recorder/autoSave/cache 등 조용히 삼키던 실패 지점에 흔적만 추가(제어 흐름 불변). `rendererStore.errors` 는 최근 50건 상한.
- **GL 에러 표면화**: `core/gl/glError.ts` 의 DEV 한정 `checkGlError` — program 링크·FBO 셋업은 무조건, 드로우 루프는 120프레임 스로틀(`gl.getError()` 동기 플러시 비용 회피). context lost/restored 상세 로깅.
- **진단 패널 + 진단 정보 복사**: StatusBar `🛈 Diagnostics` 토글이 `debugUiStore.open` 을 켠다. `DiagnosticsPanel` 은 `subscribeLog` 로 실시간 갱신되는 로그 리스트(레벨/카테고리 필터 + Clear), `Copy` 는 `buildDiagnosticsReport`(로그 + GL renderer/version + 렌더 통계 + userAgent/화면/DPR + 그래프 노드·엣지 수)를 클립보드로(미지원 환경은 안전 폴백). GL 어댑터 identity 는 컨텍스트 생성 시 `rendererStore.glInfo` 에 1회 캡처.
- **검증**: Vitest 단위 — `log.test.ts`, `debugUiStore.test.ts`, `diagnosticsReport.test.ts`, `DiagnosticsPanel.test.tsx`, `glError.test.ts` + program/framebuffer 보강. Playwright E2E `phase-16-diagnostics.spec.ts` — StatusBar 토글로 패널 열기 → 버퍼의 로그 엔트리 표시 → Clear 동작.

### Phase 36 — 실행 파이프라인 가시성 I (정직성 회복) (완료)
학습 가시성 개선 라운드(`docs/learnability-plan-2026-08.md`) T1. 관통 원칙: **자동화를 없애지 말고, 자동화의 결과를 1급 UI로 승격하라** — 자동 vertex 대체·자동 시스템 유니폼 주입·고정 mesh attribute 계약은 그대로 두고, `ExecutionPlan`이 이미 알고 있는 사실을 UI로 올린다. 신규 계산은 거의 없다.
- **A-1 (풀스크린 대체를 정직하게 표시)**: mesh 입력이 없거나 해석되지 않아 컴파일러가 `fullscreen.vert`로 대체한 Shader 노드가, 사용자에게는 여전히 `basic.vert` 소스를 편집 가능한 `vertex.glsl`로 보여주던 오정보를 없앤다. `compile.ts`의 `ExecutionPlan.fullscreenByNode`(노드ID→불리언, fatal 에러로 프로그램이 링크되지 못한 경우도 커버)를 `Viewport/index.tsx`의 recompile에서 `passPlanStore`로 발행. 그래프 형태로부터의 추론은 0건 — mesh 에셋 미로드 등으로 실제로는 fullscreen에 떨어지는 케이스까지 정확하다. `StageTabs`의 vertex 탭 라벨이 `fullscreen.vert (auto)`로 바뀌고 `ShaderNodeView`에 `FullscreenBadge`가 표시되며, `CodeEditor`는 `fullscreen.vert?raw`(컴파일 시 실제로 쓰이는 것과 byte-identical한 소스)를 CodeMirror `Compartment`로 읽기 전용 전환해 보여준다 — 편집 불가 안내 문구(`vertex-auto-note`)도 함께. vertex 에러 오버레이 발췌(`compileErrorInfo.ts`)가 화면에 보이는 소스와 이제 provably 일치.
- **D-1 (Pass Inspector, L5 해소)**: "이 프레임에 실제로 무엇이 어떤 순서로 실행되는가"를 보여주는 뷰가 그동안 없었다. `passPlanStore`(leaf 스토어)가 recompile 시 `plan.passes[]`의 위상 순서·FBO 크기/배율·mesh 출처(fullscreen/primitive/asset/compute)·sampler 바인딩(uniformName·소스 노드·유닛)을 얕은 행 요약으로 보관하고, compute 패스의 ping-pong `read`(A/B)는 라이브 클로저로 폴링해 RAF 경로에 store write를 추가하지 않는다. `PassInspector`는 `StatusOverlays`의 기존 하단 트랜지언트 오버레이 슬롯(디자인 정본 v2.2가 diagnostics/problems 2종 시분할만 정의 — Pass Inspector 3번째 슬롯 추가는 dc 미정의 지점의 잠정 결정이며 design-request v2.3 AA1로 디자이너에게 발행됨)에 표 형태로 렌더. `debugUiStore`의 상호 배타가 2원→3원으로 확장(`passesOpen`). StatusBar `▤ Passes` 버튼으로 토글.
  - **렌더러 수명과 그래프 사실의 분리**: `passPlanStore.published`가 "이 스냅샷 뒤에 살아 있는 렌더러가 있는가"를 들고 있다. Viewport가 언마운트되면(패널 ✕ = 리마운트 없음) 이 플래그만 내려가고 **페이로드는 남는다** — `rows`는 "이 프레임에 도는 것"이라 Pass Inspector가 표를 감추고 `renderer not running — open the Viewport panel to see this frame's passes`(빈 상태 2종 중 하나, `pass-inspector-empty`)를 대신 보여주지만, `fullscreenByNode`·`varyingsByNode`·행별 `silentWarnings`는 "이 그래프가 어떻게 생겼는가"라서 패널 개폐로 참·거짓이 바뀌지 않는다. 이전에는 언마운트가 스토어를 통째로 비워, 그래프를 한 글자도 고치지 않았는데 StatusBar가 `no problems`를 단언하고 A-1 표시가 통째로 뒤집혔다(배지 소멸, vertex 탭이 auto/readOnly를 잃고 실행되지 않는 소스를 편집 가능하게 열어 줌).
- **C-1 (시스템 유니폼 섹션 — 바인딩 여부·현재 값)**: Inspector의 "System uniforms (auto)" 섹션을 "System uniforms (auto-bound)"로 확장한 `SystemUniformsSection` 컴포넌트로 분리. `systemUniformStatus.ts`의 `systemUniformBinding(name, ownerKind, isFullscreen)`이 `execute.ts`의 실제 바인딩 로직(`bindSystemUniforms`/`bindComputeSystemUniforms`)을 그대로 미러해, compute 노드는 `u_time`/`u_frame`만 bound(나머지 "not bound (compute pass)"), fullscreen shader 패스는 `u_view`/`u_proj`/`u_model`/`u_camera`가 "not bound (fullscreen pass)"로 표시된다(A-1의 `fullscreenByNode` 발행을 그대로 재사용 — 그래프 형태 추론 0건). 미바인딩 행은 이름/타입 색이 `var(--text-disabled)`로 낮아지고 note가 옆에 붙는다. 판정에는 **그 노드의 패스가 실제로 발행됐는지**(`hasPass`)도 들어간다 — 프로그램 링크 실패나 compute VAO 할당 실패로 `compile.ts`가 `passes.push` 전에 `continue`한 노드는 `fullscreenByNode` 엔트리만 남고 행은 사라지는데(셰이더 에러는 fatal validate가 아니라 플랜은 그대로 발행된다), 그 상태에서 `u_time`이 계속 흐르면 "셰이더는 도는데 그림만 없다"로 읽힌다. 그런 노드는 `not bound (no pass for this node)` + 값 `—`로 표시한다. 현재 값은 **이미 발행된 스토어 값만** 500ms 폴링(RAF 구독 아님, StatusBar의 u_time 샘플링 선례)으로 표시 — `u_time`(`timeStore.simTime`), `u_mouse`(`mouseStore`의 `mouseVec4` 스냅샷, xy 정수), `u_resolution`(`passPlanStore`의 해당 노드 `ShaderPassRow.width×height`). `u_frame`/행렬류/`u_camera`는 실값이 RAF 로컬 파생이라 발행 경로가 없어 "—"(followup 기록, 새 RAF 발행 0건 원칙 유지). 설명 문자열은 기존 `SYSTEM_UNIFORM_DESCRIPTIONS` 그대로 재사용(신규 사전 0건).
- **B-1 (Mesh attribute 계약 노출)**: 모든 프리미티브·OBJ·glTF가 실제로는 `a_position(vec3)·a_normal(vec3)·a_uv(vec2)` 고정 계약이라는 사실이, 그동안 `mesh` 포트 위에서는 타입명(`mesh`) 하나로만 뭉개져 보이지 않았다. `core/assets/meshContract.ts`의 `meshContractFor(node, asset)`이 asset 바인딩 시 `GeometryHandle.data`를, 아니면 렌더 경로가 실제로 호출하는 `makePrimitive`를 그대로 읽어 attribute 목록·vertexCount·indexCount·`glPrimitiveLabel` 기반 draw-mode 라벨을 계산(정적 상수 하드코딩 0건 — 값이 바뀌면 이 표시도 함께 바뀐다). `MeshNodeView` 카드에 `mesh-contract` 블록(attribute 요약 + `N verts · M idx · TRIANGLES`)을 상시 표시(기존 `N verts` 부분 문자열 호환 유지), Inspector에 신설된 `MeshInspectorSection`(Compute Attributes 섹션 선례를 그대로 복제 — 칩 + mono 속성 행)이 같은 계약을 보여준다. `PortHandle`에 `tooltip` prop을 추가해 mesh 출력 포트에 attribute 요약을, `ComputeNodeView`의 mesh 출력 포트에는 "mesh (TF ping-pong buffer)" 안내를 달아 — compute의 mesh 출력이 정적 메시가 아니라 매 프레임 갱신되는 버퍼임을 구분한다.
- **번들**: 순수 UI 노출 확장(신규 계산 최소) — 엔트리 청크 게이트(T0, `scripts/check-bundle-size.mjs`) 한도 내 유지.
- **검증**: Vitest 단위 — `systemUniformStatus.test.ts`(8개 시스템 유니폼 × 3개 컨텍스트(shader-fullscreen/shader-mesh/compute) 매트릭스, execute.ts 바인딩 로직 회귀 가드), `meshContract.test.ts`(프리미티브 5종 전부 고정 계약 + indexCount 유/무 + asset 경로 + `attrTypeLabel`), `PortHandle.test.tsx`(tooltip→title 포워딩), `nodeViews.test.tsx`(MeshNodeView의 mesh-contract 텍스트, primitive/asset 두 경로 — asset 경로는 zustand SSR 스냅샷 한계로 client render 사용), `Inspector.test.tsx`(u_view 행이 fullscreenByNode 시딩에 따라 data-bound/note 전환, u_time 값이 폴링 tick마다 갱신, mesh 노드 선택 시 mesh-attributes 섹션), `passPlanStore.test.ts`/`passInspectorFormat.test.ts`/`PassInspector.test.tsx`/`FullscreenBadge.test.tsx`/`StageTabs.test.tsx`/`debugUiStore.test.ts`/`StatusOverlays.test.tsx`/`StatusBar.test.tsx`/`compile.test.ts`/`CodeEditor/index.test.tsx`(A-1/D-1 커버). 기존 Playwright Phase 1~35 스펙 전량 회귀 가드로 유지 — 신규 `tests/e2e/phase-36-pipeline-visibility.spec.ts`(A-1 기본/Chain 데모 정직성 왕복·읽기전용, C-1 u_view 바인딩 전환, D-1 executePlan 순서·해상도 배율·샘플러·3원 배타·컴퓨트 ping-pong, B-1 mesh-contract/mesh-attributes)가 이번 라운드(T1)의 회귀 가드.
- **비범위 (Out of scope — 별도 백로그)**: `u_frame`/뷰-프로젝션-모델 행렬/`u_camera`의 실제 현재값 발행(RAF 로컬 파생이라 이번 라운드의 "새 RAF publish 금지" 원칙과 상충 — T2 이후 별도 검토), 미연결 sampler·미사용 유니폼 경고(E-1), 연결된 유니폼의 슬라이더 무력화 표시(E-4), mesh attribute 소비 여부(선언 안 된 attribute의 조용한 스킵, B-2) — 전부 T2.

### Phase 37 — 조용한 실패의 진단 승격 (T2)
학습 가시성 개선 라운드(`docs/learnability-plan-2026-08.md`) T2. Phase 36이 노출한 `passPlanStore` 배관을 확장해, GL 레이어가 그동안 조용히 삼켜 온 실패들을 1급 진단으로 승격한다. 신규 스토어·신규 발행 지점 없음 — 기존 recompile→`passPlanPublish`→`passPlanStore` 경로 하나에 필드를 더한다.
- **E-1 (미연결 sampler / 미사용 유니폼 경고)**: recompile마다 shader pass별로, 컴파일된 소스(`plan.compiledVertexSource` + `fragmentSource`)의 선언 유니폼을 링크된 프로그램의 active uniform(`program.uniforms`) 및 연결된 엣지(sampler/paramBinding)와 비교해 `passPlanStore`의 `ShaderPassRow.silentWarnings`로 발행한다. `core/graph/silentUniforms.ts`(순수 모듈)가 규칙을 계산: active가 아니면 `uniform-inactive`, active인데 sampler이고 미연결이면 `sampler-unconnected`, active이고 엣지도 있지만 **소스 노드가 이 프레임에 텍스처를 전혀 내지 않으면** `sampler-source-empty`. `ProblemsPanel`이 이를 `silent-warning-row`(기존 `problems-card` 마크업 재사용)로 렌더하고 severity 칩(warning)과 `StatusBar`의 문제 수에 합산한다. 미사용 유니폼 문구는 GLSL 옵티마이저의 제거·사용자 오타·전처리기 분기로 컴파일되지 않은 선언을 구분할 수 없어 **원인 중립 비단정 톤**을 쓴다(`parseUniforms`는 `#ifdef`를 평가하지 않는 줄 스캐너라 죽은 분기의 선언도 declared에 들어간다). 미연결 sampler 문구도 비단정 톤이다 — 미연결 sampler의 uniform은 기본값 0으로 텍스처 유닛 0을 읽으므로, 같은 패스에 연결된 sampler가 있으면 그 첫 텍스처(유닛 0)를 그대로 샘플링한다("불투명 검정(0,0,0,1) 또는 같은 패스의 다른 텍스처(유닛 0)가 샘플링될 수 있습니다" — 아무것도 바인딩되지 않은 유닛의 샘플링 결과는 GLES 3.0 §3.8.13의 불완전 텍스처 규칙에 따라 알파가 **1**이다. 알파 0으로 적었던 초판은 `if (m.a < 0.5) discard;`류 판단을 정반대로 오도했다).
- **E-1 확장 (`sampler-source-empty`)**: 엣지의 존재는 바인딩이 아니다. 파일을 아직 고르지 않은 Image 노드(`assetId: null`)나 복원된 세션에서 에셋이 사라진 Image 노드가 sampler 포트에 연결돼 있으면 `execute.ts`의 `bindSamplers`가 그 유닛을 **통째로 건너뛴다**(`uniform1i`도 `bindTexture`도 없음). `passPlanPublish.ts`의 `emptySourceSamplers`가 `bindSamplers`와 같은 조회 순서(pass → `plan.imageTextures` → 외부 소스)로 이 집합을 계산해 E-1에 넘기고, Pass Inspector의 Samplers 칸은 같은 집합을 `row.silentWarnings`에서 되읽어 `u_tex ← image1 (미바인딩)`으로 표기한다(배정되지 않은 유닛 번호는 찍지 않는다). shader/compute 소스는 컴파일 실패 시에도 블랭크 텍스처가 바인딩되므로, webcam/video/audio는 프레임마다 텍스처가 오가므로 각각 해소된 것으로 취급한다.
- **E-4 (연결된 유니폼의 슬라이더 무력화 표시)**: (target=노드, targetHandle=유니폼) 엣지가 있으면 Inspector 컨트롤이 disabled + `driven by <노드명>` 표시, Sampler inputs 행도 연결 소스/미연결 표시.
- **B-2 (mesh attribute 소비 여부 체크)**: `uploadMesh`에 전달된 `program.attributes`와 `MeshData.attributes` 매칭 결과를 `ShaderPass.meshAttributeUse`(compile.ts)로 계산하고 `passPlanStore`까지 그대로 실어 보낸다. 여러 소비자에 걸친 "any consumed" 집계는 `core/graph/meshConsumption.ts`(순수 모듈)가 담당해 `consumed`/`skipped`/`unknown` 세 상태를 낸다. Mesh Inspector 섹션(`MeshInspectorSection`)에 속성별 ✓/스킵 마커를, `MeshNodeView` 노드 카드에는 스킵된 attribute만 골라 경고 라인을 표시한다(전부 소비되거나 소비자가 없으면 렌더하지 않음 — 오타 탐지 장치로서의 신호 대 잡음비 유지).
- **번들**: 순수 진단 노출 확장, 신규 스토어 0건 — 엔트리 청크 게이트(T0) 한도 내 유지.
- **검증**: Vitest 단위 — `silentUniforms.test.ts`(sampler 미연결/uniform inactive/정상/시스템 유니폼 inactive/paramBinding bound 각 케이스 + 비단정 톤 메시지), `meshConsumption.test.ts`(소비자 0/1/다중/목록에 없는 attr), `passPlanPublish.test.ts`(fakeGl 픽스처로 silentWarnings·meshAttributeUse 확장 단언), `passPlanStore.test.ts`/`PassInspector.test.tsx`(신규 필수 필드 리터럴 갱신), `ProblemsPanel.test.tsx`(silent-warning-row 렌더·칩 합산·클릭 select·0건 시 No problems), `StatusBar.test.tsx`(silentWarnings 합산), `nodeViews.test.tsx`/`MeshInspectorSection.test.tsx`(B-2 마커 3상태). Playwright — 신규 `tests/e2e/phase-37-silent-failures.spec.ts`(sampler-unconnected 발생·해소, uniform-inactive, 행 클릭 시 선택, mesh attribute 스킵 표시·소비자 제거 시 소멸). 기존 Phase 1~36 스펙 전량 회귀 가드로 유지 — 기본/Chain/컴퓨트 데모는 경고 0건.

### Phase 38 — 멘탈 모델 교정 (기본값·렌더 상태·좌표계)
학습 가시성 개선 라운드(`docs/learnability-plan-2026-08.md`) T3. Phase 36/37이 "실행 파이프라인이 이미 아는 사실"을 노출했다면, 이번 라운드는 사용자가 **틀리게 추측하고 있던 것**(초기값의 출처, 렌더 상태의 존재, 좌표계 규약, 데모가 무엇을 가르치는지)을 바로잡는다.
- **C-2 (`uniformValues` 하드코딩 → GLSL `@default`)**: 새 Shader/Compute 노드는 이제 `uniformValues: {}`로 태어난다. 노드 생성 코드(`AddNodePill`/`CommandPalette`)가 소스 어디에도 근거 없는 값(`u_baseColor: [0.5, 0.7, 1.0]`)을 몰래 심던 것을 제거하고, 초기 렌더 값은 GLSL 소스의 `@default` 힌트(`starter.frag`의 `// @color @default 0.5, 0.7, 1.0`)로 이관했다. `uniformParser`의 `UniformSpec.hasExplicitDefault`가 "힌트로 명시된 기본값"과 "이름 기반 휴리스틱 기본값"(`defaultRangeFor`)을 구분하고, `compile.ts`가 컴파일 시점에 `hasExplicitDefault`인 유니폼만 패스의 **별도 필드 `seededDefaults`**로 시딩한다(`withExplicitDefaults(source, {})`). 시드를 `uniformValues`에 병합하지 않는 이유: Viewport가 매 RAF tick `pass.uniformValues = node.uniformValues`로 핫패치하므로, 병합된 시드는 첫 draw 전에 통째로 덮여 GPU에 도달하지 못한다(실제 회귀 사례 — 신규 노드가 근흑색 렌더). 불변식은 항상 **저장된 값 > `@default` > GL zero** — `execute.ts`의 `bindUserUniforms`가 매 프레임 `{...seededDefaults, ...uniformValues}`(그 위에 param 엣지)를 합성해 이를 보장하며, 기존 저장 프로젝트(autosave/share URL/데모의 의도된 아트디렉션)는 하위 호환으로 그대로 이긴다. HTML 내보내기는 별도 경계다: standalone player에는 `@default` 파서가 없으므로 `htmlExport.ts`가 직렬화 직전에 shader/compute 노드의 `uniformValues`를 `withExplicitDefaults`로 구체화한다(내보내기 전용 — 일반 직렬화/autosave/share는 저장값 그대로). vertex 쪽 시드 원본은 **player가 실제로 컴파일할 소스**다 — mesh 엣지가 없으면 player도 `FULLSCREEN_VERT`로 대체하므로 그 경우 vertex 소스를 시드에서 제외한다(빈 문자열). 그러지 않으면 어느 런타임도 바인딩하지 않는 값이 내보낸 JSON에 남고, 재임포트 시 "저장값"으로 승격돼 나중에 mesh를 연결한 순간 `@default`를 이겨 버린다. 휴리스틱 기본값까지 시딩하지 않는 것은 의도된 결정 — 그러면 기존 프로젝트의 미저장 color-명 유니폼이 검정→흰색으로 바뀌는 광역 동작 변경이 된다.
- **E-2 (렌더 상태 표시, L4 해소)**: Pass Inspector 각 행에 해당 패스의 blend/cull/depth 상태를 노출한다. 이 앱은 알파 블렌딩을 어디서도 활성화하지 않고 backface culling도 항상 꺼져 있다 — 즉 **패스 안에서** 알파 블렌딩은 일어나지 않는다. 단 `outColor.a` 자체는 무시되지 않는다: 패스 FBO에 기록되어 다운스트림 샘플링에서 읽히고, 최종 캔버스 합성(컨텍스트가 `alpha:true` 기본값 + `premultipliedAlpha:false`)을 거쳐 브라우저 페이지 합성에 가시적으로 반영된다(실측: `outColor.a = 0.0`이면 뷰포트가 페이지 배경으로 뚫림). Pass Inspector 푸터 문구는 이 정밀한 사실을 그대로 서술한다. depth test가 패스 종류(풀스크린 여부)에 따라 자동으로 켜지고 꺼진다는 것도 함께 표시한다.
- **E-3 (텍스처 파라미터 표시, L2 해소)**: Image 노드와 Shader(중간 FBO) 노드에 실제 텍스처 파라미터(wrap/filter/mipmap 유무)를 노출한다. 중간 렌더 타깃 텍스처와 불러온 이미지 텍스처는 서로 다른 파라미터로 생성되어, 같은 GLSL 샘플링 코드라도 어느 쪽을 읽느냐에 따라 결과가 달라질 수 있다는 사실을 UI가 설명한다.
- **F-1 (HelpModal 좌표계 카드, L3 해소)**: HelpModal에 UV 원점·`gl_FragCoord`·`u_mouse`·이미지 텍스처의 Y-flip이 어떻게 서로 맞물리는지 한 장으로 정리한 카드를 추가한다.
- **F-2 (데모 레슨화)**: 기존 데모 5종(Sphere/Torus/Chain/Split/Particle) 전부에 순수 시각용 Group 노드로 단계별 설명을 붙였다 — Sphere/Torus는 "1·Mesh → 2·Shader → 3·Output", Chain은 "1·Generate(mesh 없음→fullscreen quad) → 2·Filter(이전 FBO를 u_tex로 샘플) → 3·Display", Particle은 "1·Compute(TF ping-pong A/B) → 2·Render(POINTS)", Split은 "파이프라인" + "각 단계를 Output으로 분기 — 화면 3분할" 두 그룹. Group 노드는 `validateGraph`/`compileGraph`/`executePlan`에 전혀 보이지 않는 순수 편집기 스캐폴딩(`core/graph/types.ts`의 `GroupGraphNode` 문서 주석 그대로)이라 ExecutionPlan 패스 수·순서는 무변경이다. 자식 관계는 `graphStore`의 `parents` 맵(그룹 선례 = `groupSelected`)을 그대로 재사용 — 새 직렬화 필드·마이그레이션 0건. 데모를 불러오는 4개 호출부(`BootstrapGate`/`AppToolbar`/`CommandPalette`/`WelcomeOverlay`) 전부가 각 데모의 `*_PARENTS` 맵을 `setGraph(graph, layout, parents)`로 함께 전달하도록 갱신됐다.
- **번들**: C-2는 순수 리팩터(신규 계산은 파서 재사용), F-2는 데이터 리터럴 추가뿐이라 엔트리 청크 게이트(T0) 한도 내 유지.
- **검증**: Vitest 단위 — `uniformParser.test.ts`(`hasExplicitDefault`가 스칼라/벡터 `@default`에서만 true, 이름 휴리스틱 단독으로는 unset), `uniformDefaults.test.ts`(explicit만 시드·stored가 `@default`를 이김·system/sampler/matrix 제외·입력 불변성), `compile.test.ts`(shader/compute 양쪽 패스가 `seededDefaults`에 시드를 싣고 `uniformValues`는 저장값 그대로인지), `execute.test.ts`(Viewport식 핫패치로 `uniformValues`를 빈 맵으로 교체한 뒤에도 시드가 업로드되는지 + 핫패치된 저장값이 시드를 이기는지 — C-2 회귀 재현 가드), `htmlExport.test.ts`(내보낸 HTML의 임베디드 프로젝트에 `@default`가 구체화되고 저장값이 이기며 앱 쪽 그래프는 불변), `starter.test.ts`(`u_baseColor`의 `hasExplicitDefault`+`defaultValue` 단언), `demoGraph.test.ts`(데모 5종 모두 validateGraph 무변경·그룹이 자식보다 선행·`parents`가 실재 그룹만 참조·기능 노드 kind 구성 불변·라벨 비어있지 않음). Playwright — 신규 `tests/e2e/phase-38-defaults-and-lessons.spec.ts`(AddNodePill로 만든 새 Shader의 `uniformValues`가 `{}`이면서도 뷰포트가 `@default` 글로우의 blue 채널 평균(>60)까지 실제 렌더 — 비영 픽셀 비율만으로는 starter.frag의 sin 항이 회귀를 가리므로 채널 평균을 단언한다, 저장 경로는 `uniformValues`에 키가 생김, 부팅 데모에 레슨 그룹 라벨과 `parents`가 존재, Presets→Chain 로드 후에도 그룹 라벨 표시). 기존 Phase 1~37 스펙 전량 회귀 가드로 유지.
- **비범위 (Out of scope)**: E-2/E-3은 병렬 유닛이 구현 — 이 항목은 동작 서술만(코드 참조 없음). 실제 블렌딩/텍스처 파라미터를 노드에서 *조작 가능*하게 만드는 것은 별도 결정(D-4) 대기 중.

### Phase 39 — varying 계약 시각화 (T4)
학습 가시성 개선 라운드(`docs/learnability-plan-2026-08.md`) T4/A-2. GLSL이 vertex `out`과 fragment `in`을 이름으로 암묵 링크한다는 사실은 이 앱 어디에도 포트/엣지로 드러나지 않는다 — 불일치는 WebGL 링크 에러(또는 더 나쁘게, 조용히 미정의인 값)로만 나타났다. `core/glsl/varyingContract.ts`가 기존 `buildSymbolTable`(Phase 24~28의 심볼 테이블 인프라)을 그대로 재사용해 두 스테이지의 선언을 diff한다 — 신규 GLSL 스캐너 0건.
- **계약 계산**: `computeVaryingContract(vertexSource, fragmentSource)`가 vertex의 전역 `out`/`varying`과 fragment의 전역 `in`/`varying`을 이름으로 매칭해 `linked`(타입 일치) · `unused`(vertex만 선언, fragment 미수신) · `missing-out`(fragment만 선언) · `type-mismatch`(이름은 같으나 타입 다름) 네 상태로 분류한다. `fragmentUsed`는 GLSL ES 3.0의 링크-타임 "statically used" 조건의 근사치(주석 마스킹된 fragment 소스에서 선언 자신을 제외한 최소 1회 추가 참조)로, 선언만 되고 참조되지 않는 varying은 링크 에러를 내지 않으므로 경고 대상에서 제외한다. 콤마 다중 선언(`out vec2 v_uv, v_st;` — 합법 GLSL)은 심볼 테이블의 선언자 walk(`RE_STORAGE_DECL` + `splitTopLevelDeclarators`)가 전 선언자를 수확하므로 정상 진단된다 — 과거 단일 선언자 정규식은 이 줄 전체를 거부해 두 이름 모두 확신에 찬 거짓 missing-out 경고가 됐다. 한 줄에 `;`로 끝나는 선언이 둘 이상 있는 경우(`out vec2 v_uv; out vec3 v_n;`, 또는 한 줄짜리 `struct L { vec3 c; };` 뒤에 이어 쓴 선언)도 수확된다 — `parseSymbolTable`이 줄마다 한 번만 매칭하던 것을 **줄 안에서 반복 스캔**으로 바꿨다(괄호 균형이 맞는 지점에서만 재시도하므로 struct 멤버나 같은 줄에서 연 함수 본문이 전역으로 잘못 수확되지 않는다). 이전에는 두 번째 이후 선언이 심볼 테이블에서 통째로 사라져, 링크에 성공하는 프로그램 옆에 확신에 찬 `missing-out` 경고(반대 방향으로는 소비 중인 varying의 `unused` 단정)가 붙었다. `confident` 플래그는 전처리기 분기(`#if`/`#ifdef` 등), GLSL 인터페이스 블록, 줄바꿈으로 감싼 storage 선언(`out vec2 v_uv,` 후 다음 줄 계속), **본문에 storage/보간 한정자를 담은 `#define`**(`#define VOUT out` — 심볼 테이블은 매크로를 전개하지 않는다)이 어느 한쪽 스테이지에 있으면 꺼진다 — 심볼 테이블이 조건부 분기를 평가하지 않고, 인터페이스 블록 내부 멤버를 파싱하지 않으며, 줄 단위 파서라 감싼 선언의 다음 줄을 못 보기 때문에, 이런 형태를 "missing"으로 잘못 보고하느니 판정을 보류한다(`#define PI 3.14` 류는 본문에 한정자 토큰이 없어 걸리지 않는다). `confidentVaryingWarnings`는 `confident`가 꺼진 계약에서는 **항상 빈 배열**을 반환해 거짓 경고를 원천 차단하고, 같은 이유로 UI의 긍정 단언(linked ✓)도 함께 보류된다(아래 Inspector 항목).
- **발행**: `Viewport/passPlanPublish.ts`의 `buildVaryingContracts(plan, graph)`가 매 recompile마다 shader 노드별로 `plan.compiledVertexSource[nodeId]`(사용자 소스가 아니라 **컴파일러가 실제로 본 소스** — fullscreen 대체 시 `fullscreen.vert`)와 `fragmentSource`를 넘겨 `passPlanStore.varyingsByNode`(leaf 스토어, `core/`를 import하지 않도록 `NodeVaryings`/`NodeVaryingRow`를 인라인으로 미러링)에 싣는다. `compiledVertexSource`에 없는 노드(치명적 validate 실패로 `emptyPlan`이 된 경우 등)는 계약 계산에서 제외된다 — 컴파일러가 손도 대지 않은 노드에 가짜 브리지를 보여주지 않기 위함.
- **Inspector — Varyings 섹션**: `VaryingBridgeSection`(신규, `SystemUniformsSection`/`MeshInspectorSection`의 `.inspector-section`/`.inspector-label` 구조를 그대로 복제)이 각 행을 `data-status`(linked/unused/missing-out/type-mismatch)와 함께 렌더한다. `linked`는 **`confident`일 때만** ✓(`var(--success)`) — `confident=false`면 ✓도 보류되고(죽은 `#ifdef` 분기의 vertex `out`이 diff상 linked로 보이는데 실제 링크는 실패하는 경우, 녹색 체크가 ErrorBadge와 정면 모순되는 것을 막는다) 섹션 캡션에 "(파서가 확신할 수 없는 선언 형태 — 판정 보류)"가 이어 붙는다 — 긍정 단언도 경고와 같은 억제 사다리를 탄다. 섹션 루트는 `data-confident`를 노출한다. `unused`는 이름만 muted 처리, `missing-out`/`type-mismatch`는 `confident && fragmentUsed`일 때만 ⚠(`var(--warning)`) + 구체적 문구, 그 외에는 글리프 없이 "(선언만 있고 미사용 — 링크는 통과)" 또는 "(파서가 확신할 수 없는 선언 형태 — 판정 보류)"로 완화한다. fullscreen 대체 노드는 캡션에 "vertex 계약 출처: fullscreen.vert (auto)"를 이어 붙여 A-1의 배지와 같은 사실을 다시 확인시킨다. Inspector 내 위치는 uniform 검색 필터(`uniformQuery`)의 영향을 받지 않는 지점 — varying은 유니폼이 아니므로 검색어가 있거나 유니폼이 0개여도 항상 보인다.
- **ProblemsPanel — 사전 링크 경고**: 기존 "Pipeline warnings" 섹션(E-1의 `silentEntries`)에 `varyingEntries`(`confidentVaryingWarnings`로 필터된 행)를 이어 붙여, fragment가 실제로 참조하는데 vertex가 제공하지 않는(또는 타입이 다른) varying을 링크 실패 이전에 경고한다. 행 클릭 시 해당 노드를 선택하고 fragment 탭으로 전환한 뒤(`fragmentLine`이 있으면) 그 라인으로 점프한다 — `goTo`의 `exactOptionalPropertyTypes` 조건부 스프레드 선례를 그대로 따른다. 섹션 카운트·경고 칩 합산은 `silentEntries.length + varyingEntries.length`.
- **번들**: 순수 UI 노출 확장, 신규 스토어 없음(기존 `passPlanStore`에 필드 추가) — 엔트리 청크 게이트(T0) 한도 내 유지.

- **비범위 (Out of scope)**: 노드 카드 변경 — 실제 링크 실패는 이미 `ErrorBadge`가 커버하므로 카드에 사전 경고 배지를 추가하지 않는다(디자인 요청서 대상). 배열 크기 불일치(`out vec3 v[2]` vs `in vec3 v[3]`)와 보간 한정자 불일치(`flat`/`smooth` 교차)는 **탐지된다** — 둘 다 ANGLE/SwiftShader에서 실제 링크 실패인데 타입 토큰만 비교하면 같아서 confident `linked ✓`가 떴던 것을 `hasSignatureUncertainty`가 잡는다(전용 행 상태를 신설하는 대신 계약 전체의 confidence를 철회 = ✓와 경고가 함께 침묵). 서명을 **찾지 못한** 경우도 불일치와 같이 취급한다 — `declarationSignature`가 선언자 리스트 전체를 훑도록 바뀌기 전에는 콤마 다중 선언의 두 번째 이후 이름이 항상 `null`로 나와 비교가 조용히 건너뛰어졌고, 그 틈으로 링크 실패 프로그램 옆의 `linked ✓`가 되살아났다. 이들이 "의도적 비탐지"였던 것은 M4 초기 판본이며 `b0b4e74`에서 뒤집혔다 — 미탐지로 남은 것은 정밀한 원인 귀속뿐이다(어느 varying이 왜 어긋났는지는 UI에 이름 지어 주지 않고 "판정 보류"로만 표시).
